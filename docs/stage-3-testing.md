# Етап 3 — збереження навчальних файлів

Перевірено 2026-09-14: **42 тести пройдено (20 сховища + 22 домену), 0 failures, 0 errors, 0 skipped**. Збірки `assembleDebug` і `assembleDebugAndroidTest` успішні. UI instrumentation на пристрої в цьому етапі не запускалася.

## Що додано

`LearningFileRepository` зберігає метадані в Room (`learning-files.db`), а UTF-8 текст і байти PNG — у приватному каталозі застосунку `filesDir/learning-content`. Назви blob-файлів — SHA-256 вмісту, а не введені учнем назви. Файли Chromebook та зовнішнє сховище не використовуються; нових дозволів у manifest немає.

Папки, ID, назви, розміри, час зміни, вміст, Кошик і зв'язки між батьками та дітьми відновлюються при повторному відкритті репозиторію. Буфер обміну залишається лише в пам'яті.

Послідовність збереження:

1. Домен формує окремий кандидат нового стану.
2. Новий вміст записується в тимчасовий файл, синхронізується через `FileDescriptor.sync()` і атомарно перейменовується у blob. Старий вміст не перезаписується.
3. Одна транзакція Room замінює метадані та посилання на blob-файли.
4. Після успішного commit репозиторій публікує новий StateFlow.
5. Неактуальні blob-файли видаляються. Помилка очищення не скасовує вже збережений документ; очищення повториться пізніше.

Якщо запис або транзакція не вдаються, попередній стан залишається доступним. Після відкриття перевіряються хеші, розміри, дерево, імена та наявність кореня. Пошкоджене сховище повертає помилку без автоматичного очищення даних. Міграції Room не мають destructive fallback; схема версії 1 збережена в `app/schemas/`.

Один екземпляр репозиторію має обслуговувати весь застосунок. Mutex серіалізує його операції, а файлове блокування відхиляє друге відкриття того самого сховища. `open`/`close` коректно звільняють ресурси, включно зі скасуванням корутини під час відкриття.

Скопіюй увесь блок у PowerShell. Дозвіл на скрипти діє лише до закриття цього вікна:

```powershell

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
```

Для перевірки лише сховища:

```powershell
.\gradlew.bat testDebugUnitTest --tests "*LearningFileRepositoryTest"
```

Очікувано: `BUILD SUCCESSFUL`. Якщо Gradle показує `UP-TO-DATE`, попередній результат актуальний. Для примусового повторення додай `--rerun-tasks`.

Відкрити звіт:

```powershell

```

Перший запуск Robolectric може завантажувати тестовий Android із Maven Central. Локальний скрипт задає `WINDOWS_LEARNING_TEST_ROOT` як `../work/r`; домашній каталог тестового JVM — `h`, тимчасовий — `t` усередині нього. Це короткі шляхи в робочій папці, які не потребують запису в особисті каталоги. Без цієї змінної використовується `app/build/test-runtime`. У цьому середовищі тестовий Android попередньо завантажено в локальний Maven-кеш із перевіркою SHA-512.

## Що перевіряють тести

- Повторне відкриття файлової бази Room, рівність тексту, байтів PNG і метаданих.
- Вкладене копіювання, незалежність копій, Кошик та відновлення після відкриття.
- Збої перед синхронізацією blob, між записом blob та commit, і всередині реальної транзакції Room.
- Незмінність опублікованого стану після відмови й відсутність часткової копії папки.
- Очищення незавершених записів; успіх збереження навіть при помилці подальшого очищення.
- Виявлення відсутніх/пошкоджених blob-файлів, втраченої бази або рядків, циклу батьківських зв'язків і некоректного шляху до вмісту.
- Послідовність конкурентних записів, заборону другого записувача, повторний close та скасоване відкриття.

Robolectric запускає Android API 35 на комп'ютері з файловою SQLite-базою у режимі `SQLiteMode.NATIVE`, а не підставною мапою в пам'яті. Тести відмов інжектують винятки на межах операцій; це не фізичне вимкнення пристрою. Перевірка на реальному Android/Chromebook залишається окремою перевіркою при підключенні інтерфейсу.

## Як використовуватиме інтерфейс

На рівні застосунку буде один `LearningFileRepository.open(context)`. Екрани спостерігатимуть `snapshots`, а дії виконуватимуть suspend-методи create/rename/copy/paste/write/trash/restore. Repository виконує I/O на Dispatchers.IO. Поточна реалізація завантажує весь навчальний вміст у пам'ять при відкритті; потокова робота з великими малюнками ще не реалізована.

У цьому етапі repository ще не підключено до статичного Compose-екрана. На телефоні нові файлові дії не з'являться. Наступний етап — робочий інтерфейс і наскрізний сценарій із Провідником та Блокнотом.

Технічні джерела для конфігурації: [Room 2.7](https://developer.android.com/jetpack/androidx/releases/room), [Robolectric 4.14](https://github.com/robolectric/robolectric/releases/tag/robolectric-4.14).
